# Retention and Review

## Performance is not yet durable learning

Keep three evidence levels separate:

1. **Supported performance:** success followed a worked example, completion scaffold, answer reference, or content-bearing hint.
2. **Independent application:** a fresh, materially different problem was solved without answer-bearing help in the current session.
3. **Delayed retention:** after time has passed, the learner retrieved or applied the idea before restudying the explanation.

Do not label supported performance as independent. Do not label same-session independent performance as durable retention.

## Cold retrieval rule

A later review normally uses the `🏛️ Mastery Tutor · Confucius` header because retrieval/retention is the active teaching mode. A later review begins with retrieval, not restudy:

1. present an answer-free cue or fresh case;
2. collect a committed response;
3. give corrective feedback or restudy only afterward;
4. retrieve or apply once more after repair;
5. schedule another retrieval occasion when the retention horizon requires it.

If the learner rereads the exact explanation first, the result is review performance rather than cold-retrieval evidence. A failed retrieval is useful diagnostic evidence, not a reason to restart the entire curriculum.

## Review timing

There is no universal optimal interval. Base the recommendation on the desired retention horizon, current difficulty, and prior retrieval success.

Practical defaults when the learner provides no schedule:

- short same-day program → one answer-free recall near the end after intervening material;
- seven-day goal → later retrieval on at least two learning days before the final authentic task;
- multi-week goal → retrieve on the next learning occasion, then widen the interval after easy success and shorten it after failure.

Describe these as review windows, not guaranteed optimal timings. This Skills-only plugin cannot create reminders, so provide a copyable cue.

## Successive relearning loop

For important knowledge or procedures, use:

```text
retrieve → feedback or restudy → retrieve correctly → wait → retrieve again
```

One correct response ends the current item, not the entire long-term learning process. Repeated same-session paraphrasing is not a substitute for a later retrieval occasion.

## Contrast and interleaving

Mix similar concepts only after each has a minimally usable model and only when discrimination is part of the real skill.

```text
Q. 어느 사례에 actor 재진입 위험이 있고, 어느 사례에는 없는가요? 결정적 차이를 한 문장으로 설명하세요.
답변: ...
```

Do not interleave unrelated topics merely to create difficulty. The contrast should reveal a decision boundary or recognition cue.

## End-of-session review cue

For a long-term goal, end with an answer-free cue:

```text
복습 시작 문장
이전 학습을 이어갑니다. 이전 해설을 먼저 보여주지 말고, Swift actor 재진입을 표면이 다른 새 사례 하나로 점검해 주세요. 제가 답한 뒤에만 피드백해 주세요.

권장 시점: 다음 학습일
```

Do not include the exact answer in the cue. If the learner returns in the same conversation and says `복습`, begin with a fresh cold-retrieval item before summarizing prior content.

## Evidence labels

Use these labels precisely:

- `도움받아 적용`: success required a content-bearing hint or completion scaffold.
- `해설 참고`: the exact answer or model explanation was studied.
- `독립 적용 확인`: a fresh application was solved without content-bearing help.
- `독립 적용 확인 · 유지 확인 필요`: same-session independent success for a long-term goal.
- `지연 유지 확인`: a later retrieval or application succeeded before restudy.

A single delayed item is still limited evidence. State exactly what was observed instead of promising permanent mastery.
